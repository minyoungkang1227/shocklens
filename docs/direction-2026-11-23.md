## 현재 상태 (2026-11-23 점검)
- GitHub main 122afdd. 테스트 200개 통과. kfin-eval CI 2회 모두 성공.
- 새로 들어온 것: 신경망 문장 임베딩 층(engine/embedsim.py, 기본 꺼짐), kfin-eval CI(엔진이 바뀌면 collatio 정답지와 비교).
- 실제로 돈 기록:
  - 데일리 워치 보고서는 2026-11-11 하나뿐이다. data/daily/run.log가 없어서, 예약 작업이 한 번도 돌지 않은 것으로 보인다.
  - 가격·FRED 데이터 갱신도 11/11이 마지막이다. 위기 지표 파일(stress_indicators)은 아직 한 번도 받지 않았다.
  - 실전 성적표에는 예측 2건이 있고 그중 1건만 채점됐다(11/05 중간선거: 밴드 안, 크기 과소추정). 11/16 BIS, 11/18 CMS 건은 아직 기록되지 않았다.
  - analog_labels.yaml의 정답 라벨은 13건 모두 비어 있다. 그래서 임베딩 층을 켤지 판단할 근거가 없다.
  - llm_compare는 아직 한 번도 돌리지 않았다. 그래서 LLM 경로의 해석 정확도는 측정되지 않았다.
- 아침 브리핑은 클라우드 작업이 매일 쓰지만 ShockLens 엔진을 거치지 않는다. 그래서 브리핑의 정책 사건 판단이 성적표에 쌓이지 않는다.

## 순서
1. **자동 실행 복구 (이번 주)**
   - 작업 스케줄러에 ShockLensDailyWatch가 등록돼 있는지 확인한다: `schtasks /Query /TN ShockLensDailyWatch`. 없으면 등록한다.
   - 실행 시각은 PC가 켜져 있는 시간으로 잡는다.
   - 다음 날 data/daily/run.log와 보고서가 생겼는지 확인한다.
   - 밀린 기록 두 건(BIS 11/16, CMS 11/18)을 track_record --add로 넣는다.
2. **측정 기반 만들기 (이번 주)**
   - analog_labels.yaml 13건에 사람 정답을 채운다. 사건마다 '이 사건과 비슷한 과거 사건' 1~3개다. 본인 판단이 필요하다.
   - 그다음 `analog_eval --embed 0.3`으로 임베딩을 켠 것과 끈 것을 비교하고, 켤지 정한다.
   - `llm_compare`를 한 번 돌려 LLM 경로의 해석 정확도를 잰다.
3. **성적표가 30건 쌓일 때까지 모델 숫자를 바꾸지 않는다**
   - 지금은 과소추정 1건뿐이라 보정 여부를 판단할 수 없다.
   - 볼 지표는 방향 적중률, 밴드 적중률, 중심값 오차다.
   - 엔진을 바꾸면 kfin-eval CI가 깨진다. 엔진 변경은 성적표 근거가 있을 때만 하고, 그때 collatio 정답지를 함께 갱신한다.
4. **보류**
   - 새 위기 지수, 새 에이전트, GPR 트리거, 사건 라이브러리 대량 확장은 3번 결과가 나온 뒤에 판단한다.

## 나중에 검토
- 아침 브리핑과 데일리 워치를 하나로 잇는다. 브리핑의 '정량 분석 후보'가 다음 데일리 실행 때 자동으로 track_record에 들어가게 한다.
